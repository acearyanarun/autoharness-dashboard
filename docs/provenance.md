# Provenance

Every published run says where its numbers came from.

- `run.json` `provenance` is `"ci"` for workflow runs (Phase 2) or `"manual"` for fixtures.
- `run.json` `source_files` records the sha256 of every input file (listing, kani-list JSON).
- `kani.commit` / `library.commit` accept short SHAs, but `commit_is_full` flags them.
  CI runs must record full SHAs. The 2026-09-17 baseline is only known by short SHA.
- `comparability_key` hashes Kani commit, library commit, toolchain, target and
  `--bounded-arguments`. Only runs with equal keys may be compared as a change.

## Fixtures

| Fixture | Real or synthetic | Proves |
|---|---|---|
| `fixtures/kani-upstream/` | Real Kani output (Kani's own tests) | Parser handles the real format; the renderer reproduces it byte for byte |
| `tests/fixtures_small/` | Synthetic, generated by `tests/support/small_fixtures.py` using that renderer | Every reason variant, empty sections, surrounding noise |
| `fixtures/baseline-2026-09-17-x86_64/golden/` | Real per-function output of the baseline (practicum) | Classification, counts, validation at full scale |
| `fixtures/baseline-2026-09-17-x86_64/raw/` | **Pending**: original listing | End-to-end reproduction from raw stdout |

Rules: don't edit real fixtures. Don't present synthetic data as real. Never
reconstruct a missing original file.
